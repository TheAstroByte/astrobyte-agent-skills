# Dispatch a read-only reviewer

Select the reviewer through `astrobyte-review`: apply explicit reviewer requirements first, otherwise strongly recommend and prefer the newest offered GPT Sol model at the harness default reasoning level. If Sol is unavailable, ask the operator to select an available independent read-only reviewer. A strict local Sol requirement remains binding. A model name alone does not establish a usable route. Use one reviewer, adding a second only when requested or when the change is broad or high-risk.

- Cursor: use Task with `model` set to the selected available reviewer slug. Use the harness default reasoning level unless an explicit preference changes it. Instruct the task to read and review without editing files.
- Codex: use a read-only subagent with the configured model and its default reasoning effort. When a subagent is unavailable, run `codex --ask-for-approval never exec --sandbox read-only --model <model>`; the approval flag must precede `exec`.
- Claude Code: when the session offers the selected reviewer model, pipe the brief to `claude -p --model <model> --setting-sources user --tools Read,Grep,Glob --strict-mcp-config --permission-mode plan --output-format json`, adding `--effort <level>` only when a preference sets the reasoning level. GPT models require an LLM gateway that lists them in the model picker. The review counts only when the result's `modelUsage` lists the selected model alone; an unexpected fallback does not satisfy the gate. Otherwise use an installed, authenticated Codex CLI offering that model with the same read-only `codex exec` command. Without either, the gate is pending until a usable route or permitted explicit reviewer choice is available.
- OpenCode: use a configured read-only agent only when it offers the configured model. Otherwise the gate is blocked.
- Other harnesses: use read-only delegation that offers the configured model. Otherwise the gate is blocked.

When the selected model or independent read-only route is unavailable, report the missing capability and leave the push or pull request waiting. Follow explicit reviewer requirements; propose an alternative only where the resolved policy permits it. A separate review context is required even if it uses the same model as implementation. Self-review and silent model substitution do not satisfy the gate. Installation adapters are unnecessary for this runtime dispatch.
