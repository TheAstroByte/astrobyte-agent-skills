# Optional T3 routes

Read this only when personal policy enables `t3` and the current host offers the relevant tools. These runtime routes do not establish T3 installation or skill-discovery support. Verify discovery in T3 before claiming the package works there.

When offered, use `orchestrator_capabilities` to inspect models and `delegate_task` for one read-only review task per selected council member or Sol round. Resolve actual model identifiers from capabilities. Keep the configured reviewer, default effort unless selected otherwise, scoped brief, revision, and finding ledger. Use each task's returned identity for its supported continuation mechanism; do not guess thread IDs or storage identifiers.

For PR monitoring, use one `watch_pull_request` owner after handling current checks and feedback. A delegated reviewer does not own the watch. Treat a wake as new evidence and re-read the live PR; it is not a readiness or merge decision. Use `unwatch_pull_request` on handoff, a blocking question, or stopping the task. Reconnect after an actual resume only when the earlier watch is known to have ended.

Use the host's documented rate-limit and retry signals. Do not start competing watchers or promise that ending a turn will continue work unless a real wake route is active. If a required T3 capability is absent, use a supported native route that satisfies the same configured model and authority contract, or report the missing capability. Enabling this option does not install providers or authorize external actions.
