# Optional personal PR workflows

## Outcome

Offer one optional PR-workflow package through adoption and personalization. Preserve the shared default, existing installations, and a simple setup for one harness. Keep the same configuration path usable for several selected harnesses.

The package provides explicit finish, Sol review, council, continuation, and PR-feedback operations. Both full-stop and full-send leave work unmerged. Sol is the recommended independent reviewer wherever available. Council asks for its models on first use on the current system, then stops at a bounded round limit unless the operator extends it.

## Delivery

1. Unify installation and personalization inputs. Add validated personal optional-package selection and reusable workflow policy, preserving the default profile and legacy behavior.
2. Add the optional package, local first-use state, provenance, and adoption guidance. Build this branch on the foundation and leave both pull requests for owner review.

The operator authorized parallel independent work and a combined final handoff. Repository merges and active-machine installation remain separate owner decisions.

## Scope

The foundation changes preference validation, installation input resolution, runtime policy, generated runtime helpers, focused tests, and documentation. The package changes its own instructions, helper, tests, catalog registration, notices, and optional-use guidance. Canonical baseline profiles, default bundle memberships, unrelated skills, and routing lifecycle behavior remain unchanged.

Use one validated personal delta with optional skill names and reusable PR-workflow options. Keep exact models, routes, credentials, and repository-specific first-use answers in local state. Follow the existing precedence for personal, machine, project, and task choices. Optional-package selection is an explicit installation choice, not new external authority.

## Evidence

- Compare default profile membership and generated policy resources before and after.
- Run preference, installation, package portability, state-helper, and legacy-compatibility tests.
- Execute the installer and installed helpers against temporary homes with no source imports.
- Verify one, shared two-harness, and five-harness selections.
- Exercise council and repository setup as data persistence without calling real models or modifying a PR.
- Forward-test explicit invocation, unmerged finish behavior, and prototype review scope in an isolated read-only agent scenario.
- Run repository validation and all tests, then obtain the required independent Sol review before each push or pull request.

A missing model or monitoring route remains a reported capability limit. T3 runtime guidance is optional; installation and live wakeups are not claimed without observed verification.

## Mode and authority

Explore and prototype work proves the requested path. Uncommon, unobserved error handling is deferred unless it affects the actual task or the operator requests it. Sol and council receive the same mode and acceptance contract. Neither finish operation silently promotes disposable work or grants merge permission.

Representative task outcomes can improve later versions: retain reviewer-demanded work outside the prototype contract as one signal, and judge it against the declared mode and observed behavior.
